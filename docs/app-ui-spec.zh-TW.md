# 寫一個 catnip app

**語言：** [English](app-ui-spec.md) · 繁體中文

app 提供什麼、平台提供什麼、兩者在哪裡交會。文中描述的能力是目標設計，有些尚未實作。

## 畫布

320x240，橫向，深色主題。有兩種模式，app 不特別要求就是第一種。

**一般模式。** 平台畫的標頭，底下的主區域是你的。

```text
┌──────────────────────────────────────────────┐
│ [BATTERY]      [TITLE]           [PAGE]      │  標頭 — 平台的
├──────────────────────────────────────────────┤
│                                              │
│                  主區域                       │  你的
│                                              │
└──────────────────────────────────────────────┘
```

你提供兩樣東西：**一個標題**與**一棵內容樹**。frame 會在**可見**的那一頁外面畫標頭——包括你 push 出來的頁，所以對話框跟 root 一樣有框。

**全螢幕模式**（`frame: "bare"`）。沒有標頭，整片 320x240 都是 app 的，給真正是一塊畫布的東西——遊戲、時鐘面、訊號圖。
它換到的是**空間，不是座標**：規則 1 依然成立，你依然是建一棵沒有幾何的樹。

### 主區域放什麼

四種形狀，沒有第五種。四者都是 `list`，差別只在平台怎麼排。

| 形狀              | 什麼時候                   | 排法                           |
| ----------------- | -------------------------- | ------------------------------ |
| **一個 icon**     | landing page——貓、開場畫面 | 置中，獨自一個                 |
| **最多六個 icon** | 一組可選的東西             | **3x2 grid**，聚焦的那個加外框 |
| **文字列**        | 更長的、或需要文字說明的   | 一列一行                       |
| **數值**          | 設定——是量，不是選擇       | **直立 bar**，並排             |

前三種回答的都是「哪一個？」。第四種之所以存在，是因為它們都答不了「多少？」——一個量沒有天然的列、也沒有天然的 icon，硬套一種形狀只會把數字擺到不是重點的位置。
它是 `ui.list{ layout = "mixer" }`：每個子節點帶 `value`(0–100，bar 填到哪)與 `value_text`(印在上面的讀數)，而**短按 A 把那一欄推到下一個值**。
高度就是數字，所以整頁可以互相比對；觸控目標也從一列文字變成一根與區域等高的柱子。

```text
    70%      30 s      5%     2.5 s
   ╔═══╗    ┌───┐    ┌───┐    ┌───┐
   ║███║    │   │    │   │    │███│
   ║███║    │███│    │███│    │███│
   ╚═══╝    └───┘    └───┘    └───┘
   Screen   Idle-off   LED    Breath
```

一個值是**幾個具名階的梯子**，不是連續區間，因為「下一個值」需要一份有限的清單。
挑階的時候要讓「最後一階再按一下」落在安全的地方：梯子是循環的。

超過六個是**捲動**而不是翻頁：選取帶動、視窗跟隨，跟清單完全一樣，所以捲動模型只有一套。
grid 就是 `ui.list{ layout = "grid" }`——同一個 node、同一個 `selected` 整數、同一組事件，只有排列方向不同。

**每一列都保留前導 icon 槽**，不管它有沒有 icon：glyph 14 px 加 6 px 間距，所以文字從第 20 px 開始。
是「一律」而不是「清單裡有人用到才留」——一條沒有條件的規則，而且某列後來加上 icon 時，文字不會整批位移。
**列必須有文字，icon 是選配。**

## 規則

1. **只命名，不擺放。** 說出你要顯示什麼——一個 label、一個 list、一個 icon。永遠不要求像素、座標、尺寸或角落。
2. **樹建一次，之後只寫屬性。** renderer 是 retained：它會保留為某個 node 造出來的物件，並用 table identity 比對子項。移動選取是寫一個屬性，不是重建整頁。
3. **一列就是 `[icon] [name]`，而且 icon 槽永遠都在。** 列是 `list` 的子項，可選取、可觸控。觸控事件送給**清單**，並帶上列索引。
   文字是必要的，icon 不是，而那個空間兩種情況都保留。
4. **`selected` 是你自己的。** 它是一個整數，而且只由上往下傳。平台把 `prev`/`next` post 給你聚焦中的清單，由你去動那個數字。
5. **用名字挑 icon，或自己附一個。** 內建 glyph(`folder`、`file`……)代表**類別**；你的 `icon.png` 是這個 app 的**身分**。
   不認得的 glyph 會安全退化，缺圖會退回吉祥物。內建那套是 catnip 自己的實心彩色 icon(`firmware/assets/icons`)，不是借來的符號字型。
6. **讓 `[PAGE]` 自己推導出來。** frame 依主區域放的東西自行判斷，沒有任何 API 能設定它：
   grid 數**頁**、清單數**列**、carousel 與 mixer 數**格**，單一 icon 什麼都不數、留白。
   grid 顯示 `2/3` 而不是 `8/14`，因為使用者在那裡看到的是**頁面上的位置**，不是序號。
7. **短按是主要動作，長按是次要動作——A 與 B 一致。** 短按 A 啟用；長按 A 給出「選取項目」的選項。
   app 做得到的事**永遠不出現在畫面上**——操作只存在於長按 A 之後。
8. **只有真的有得爬時才接走短按 B。** 處理掉了就從 `on_back` 回傳 truthy，沒處理就回傳 falsy 或什麼都不回。
9. **不要期待長按 B。** 那是回家，是平台的，不會抵達你任何一個 handler。電源鍵也一樣。
10. **manifest 宣告，Lua 決定。** manifest 擁有身分與外觀(`id`、`name`、`icon`);Lua 擁有行為與適用性。`id` 是兩者之間的接縫。
11. **空就是留白。** 不要列、也不要佔位字。留白是「沒有東西」的誠實呈現。

## 手勢

| 手勢         | 意義                         | 抵達你的形式               |
| ------------ | ---------------------------- | -------------------------- |
| Up / Down    | 移動選取；清單捲動跟隨       | `prev` / `next` 給聚焦清單 |
| Left / Right | 在可聚焦元件之間移動焦點     | 不傳；焦點環由平台移動     |
| 短按 A       | 啟用目前項目——數值則是下一階 | `on_click(self)`           |
| 長按 A       | **選取項目**的選項           | `on_options(self, index)`  |
| 點一列       | 選取並啟用該列               | `on_click(self, index)`    |
| 長按一列     | 那一列的選項                 | `on_options(self, index)`  |
| 滑動         | 用手指做的搖桿四方向         | 該方向本來的意義           |
| 短按 B       | 返回——pop、往上一層、或離開  | 可見頁的 `on_back(self)`   |
| 長按 B       | 回家——回到貓，不論多深       | 不傳；平台自己留著         |
| 長按電源     | 關機                         | 不傳；PMIC 自己留著        |

**滑動不是新手勢。** 它就是搖桿，只是用手指做：本來往上推的地方就往上滑，左右亦然。
觸控與搖桿是同一套小詞彙的兩種說法——「點一下就是在那一列上短按 A」本來就成立——方向遵循同一條規則，而不是為手指另造一套語法。

這有一個必須說清楚的代價，因為它是**拿掉**了一樣東西：**清單不能再用手指自由捲動。**
拖曳移動的是選取，一次一列，視窗跟著選取跑，跟搖桿完全一樣。
如果讓手指去拖視窗，選取會被留在畫面外，而那會打破整個捲動模型唯一的支柱——選取帶動，視窗跟隨。

**瀏覽與選取完全可以用觸控完成，離開不行。** 手指可以翻、可以選、可以啟用、可以叫出選項——所有在畫面之內移動的事。
返回與回家沒有對應的滑動、也沒有可點的角落：B 是實體按鍵，而且會一直是。

這條線劃在這裡是刻意的，而且它值兩次。**離開是唯一絕不能被誤觸引發的動作**——口袋、擱在玻璃上的拇指、面板讀到一滴水。
**它同時也是使用者必須永遠到得了的動作**，包括面板已經完全沒有回應的時候。實體按鍵在這兩件事上都勝過手勢，而且它是裝置上唯一如此的東西。

長按門檻是 `LONG_PRESS_MS`(600 ms)。在門檻前放開 → 短按；到門檻仍按住 → 長按，並抑制短按。

**短按 B。** 你的 `on_back` 會被呼叫，回傳值就是訊號：

- **truthy** → 你處理掉了(你往上一層目錄、清掉選取)。平台什麼都不做。
- **falsy，或根本沒有 `on_back`** → 平台動手：把你 push 在 root 之上的頁 pop 掉，否則就離開你的 app。

所以單頁 app 不用寫 `on_back`,B 照樣離開它；push 出來的對話框不用寫 `on_back`,B 照樣取消它。只有在你自己有一層要爬時才寫。要在 handler 裡直接離開，呼叫 `ui.exit()`。

```text
 貓  (home)                  ◄── 長按 B，在哪裡都一樣，永遠有效
   └─ 你進來的那一頁          ◄── 從 app root 短按 B 會回到這
        └─ app root          ◄── 短按 B 往上一層(你的 on_back)
             └─ push 的頁     ◄── 短按 B 把它 pop 掉(context menu、對話框)
```

**長按 A。** _已修訂，尚未實作。_

**任何操作都不會出現在畫面上。** 不管是 Delete、Open 還是 Reset——app 不為自己做得到的事畫按鈕，平台也不畫。
操作只存在於一個地方：**它所作用的那個項目的長按之後**，在那一按之前它哪裡都不存在。

因此一個畫面顯示的永遠是「**有什麼**」，不是「**能做什麼**」，而主區域始終是內容，不會一半內容一半工具列。
這條規則約束平台的程度不亞於約束 app：launcher 的列上也不提供任何操作。

**它以一條從底部升起的列出現。** 一排兩顆，每顆是 `[icon] [名稱]`；超過兩個就往上捲，一次一排。
它就是一個兩欄的 `layout = "grid"` 清單，所以左右在同一排走、上下換排——**沿用 grid 自己的走法，不是第三套規則**。

```text
┌──────────────────────────────────────────────┐
│ [==] 87%        File Browser           12/45 │
│                                              │
│  底下的內容仍然看得見                          │
│  ╭────────────────────────────────────────╮  │
│  │  [✓] Ok            [✕] Cancel          │  │  ← 從底部升起
│  ╰────────────────────────────────────────╯  │     往上捲有更多
└──────────────────────────────────────────────┘
```

**A 執行聚焦的動作，B 取消**——那是預設，app 可以把 B 改綁到別的東西。
平台保留一道防護：**它拒絕把 B 綁到 manifest 標為破壞性的動作**。
B 在裝置的其他地方都是逃生口，而把 Delete 放在那裡的 app，會剛好在使用者想離開的那個反射動作上誤觸。

預設那一對是 `Ok` / `Cancel`。**Cancel 並不是 B 的贅字——它是給手指的**，因為返回與回家沒有觸控，觸控使用者需要一個看得見的出口。

既然是平台畫的，`on_options(self, index)` 就改成**回答哪些動作適用**，而不是自己建一頁再 push：它回傳一串 manifest 目錄裡的 action id。
這樣每個 app 的選項長得一樣、行為也一樣——**那正是系統 icon 集存在的意義**；自己畫選單的 app，遲早會畫出一個不一樣的 Delete。

## 誰擁有什麼

|                        | 平台                                        | 你                             |
| ---------------------- | ------------------------------------------- | ------------------------------ |
| **版面**               | 所有幾何、帶高、列高、捲動                  | —                              |
| **頂列**               | 電量、標頭、`N/total`                       | 標題**字串**                   |
| **內容**               | 保留區域、繪製你的樹                        | 建那棵樹                       |
| **選取**               | post `prev`/`next`/`click`、捲動跟隨        | `selected` 整數                |
| **icon**               | 解析 glyph 名與 `icon.png`、吉祥物 fallback | 挑**哪一個** icon              |
| **短按 A / 觸控**      | 偵測、post                                  | `on_click`——「啟用」是什麼意思 |
| **長按 A**             | 偵測、帶索引 post                           | `on_options`——建 menu          |
| **短按 B**             | 你不接時負責 pop 或離開                     | `on_back`——接或不接            |
| **長按 B、電源、主題** | 全部                                        | —                              |

右欄就是你的全部。不在右欄裡的，就不是你能決定的。

## Config

旋鈕放在 manifest，行為放在 Lua。

| 旋鈕                                  | 位置     | 效果                                       |
| ------------------------------------- | -------- | ------------------------------------------ |
| `name`                                | manifest | 預設標題，也是你那一頁上的名字             |
| `icon`                                | manifest | 你的身分 icon；沒有 → 吉祥物               |
| `actions[]`                           | manifest | 動作目錄：`id`、`name`、`icon`             |
| `frame`                               | manifest | `"standard"`(預設)或 `"bare"`              |
| `counter`                             | manifest | 你不是清單的話設 `false`                   |
| `ui.title(s)`                         | Lua      | 執行期會變的標題                           |
| `layout`                              | Lua      | 清單上：`"grid"` 放 icon，`"mixer"` 放數值 |
| `on_click` / `on_options` / `on_back` | Lua      | 接走短按 A、長按 A、短按 B                 |

**`frame: "bare"`** 會拿掉頂列，把整片 320x240 給你——給真的是一塊畫布的 app(遊戲、時鐘面)，而不是清單。代價是失去電量、標題與計數；它換到的是**空間，不是座標**：規則 1 依然成立，你依然是建一棵沒有幾何的樹。

## 範例：File Browser

manifest 宣告身分與動作目錄：

```json
{
  "id": "filebrowser",
  "name": "File Browser",
  "entry": "main.lua",
  "icon": "icon.png",
  "permissions": ["fs.read", "fs.delete", "fs.reset"],
  "actions": [
    { "id": "open", "name": "Open", "icon": "file" },
    { "id": "rename", "name": "Rename", "icon": "edit" },
    { "id": "delete", "name": "Delete", "icon": "trash" }
  ]
}
```

Lua 決定行為。樹在檔案底部建一次，之後只改屬性(規則 2):

```lua
local rows = ui.list{ id = "rows",
  on_prev = function() move(-1) end,
  on_next = function() move(1) end,

  -- 短按 A 或觸控：觸控時 index 會來，短按 A 時沒有
  on_click = function(self, index)
    if index then B.sel = index; self.selected = index end
    local e = B.entries[B.sel]
    if not e then return end
    if e.is_dir then descend(e) else show_file(e) end
  end,

  -- 長按 A:menu 取決於項目，所以在這裡建
  on_options = function(self, index)
    local e = B.entries[index]
    if not e then return end
    local acts = e.is_dir and { "open" } or { "open", "rename", "delete" }
    ui.push(menu_for(e, acts))   -- 列是從目錄取出的 [icon] [name]
  end,
}

ui.screen{ rows,
  -- 短按 B：還有得爬就爬，爬到頂就讓平台把我們帶出去
  on_back = function()
    if B.cwd == "" then return false end   -- 在 root：平台離開這個 app
    up(); return true                      -- 爬了一層：平台什麼都不做
  end,
}
ui.title("SD:/")   -- refresh() 裡也要再呼叫，因為路徑會變
```

填列時要保留 node、只寫屬性——重用的列只是一次文字更新，它背後的 widget 從不重建：

```lua
local function fill_rows()
  local old, kids = rows.children, {}
  for i, e in ipairs(B.entries) do
    kids[i] = old[i] or ui.label{ id = "row" .. i }
    kids[i].text = e.name
    kids[i].icon = e.is_dir and "folder" or "file"   -- 規則 5
  end
  rows:set_children(kids)
  rows.selected = B.sel
end
```

## 首頁，以及你的 app 在哪裡被找到

_已設計，尚未實作。_

**首頁就是那隻貓。** landing page 不是 app、也不是選單；它是每一個手勢都到得了的那一頁，也是長按 B 永遠落地的地方。
它就是主區域的「一個 icon」形狀。

它兩側各有一層，而**這兩層不是同一件事的兩種做法**——一層是「**你的東西**」，另一層是「**全部東西**」。

**carousel 是精選層。** 從首頁出發，每個方向打開一個平面：上是時鐘，下是設定與偏好，左右翻過你留下來的 app。一次一個，大。

```text
                        ▲  時鐘
                        │
   apps  ◄──────────  [貓]  ──────────►  apps
                        │
                        ▼  設定與偏好
```

四個方向在這裡代表四件不同的事，這正是它是 home section 而不是一排橫著放的清單的原因。
**在 carousel 的任何一格往下都到得了設定**，不必先回到中間那隻貓才能改亮度。

設定是平台自己的頁，用的是上面那個「數值」形狀，而且它不是 app：它不在 grid 裡、不能被釘選，你寫的東西也取代不了它。
**「往下就是設定」唯一的例外是 grid**：在 grid 裡往下是下一排，因為讓一份長清單在被捲動時掉出自己，代價遠大於它省下的那一個手勢。

**grid 是全部。** carousel 其中一格是「**所有 app**」，打開後就是主區域的「六個 icon」形狀：卡上每一個 app 排成 3x2，超過六個就捲動。
找到第十二個 app 是兩個畫面，而不是十二次翻頁——**那是 carousel 單獨做不到的事**。

聚焦的 icon 加外框，而**它的名字就顯示在標頭的 `[TITLE]`**——所以 icon 底下不需要標籤，名字也還在。

**釘選讓 app 在兩層之間移動。** 在 grid 的 icon 上長按 A 會有 `Pin`，在已釘選的上面則是 `Unpin`。
清單是 `/sd/catnip/` 底下的一個檔案，因為那本來就是平台放自己狀態的地方、`fs.*` 也已經存在——**不需要新增任何能力**。
釘選跟著卡片走：換卡就沒了，而那是對的，因為那些 app 本來就跟著卡片一起走了。內建的平面不依賴這個檔案，不受影響。

**短按 B 回到你進來的地方**——從 app 回到啟動它的那一頁或那一格，從平面回到首頁。**長按 B 則是不論多深，直接回到貓。**
這正是讓兩者在 app root 不致變成同一件事的地方。

**這對你的 app 的要求。** 你的 `icon.png` 是你在 grid 與 carousel 裡的臉，而且是在真的看得清楚的尺寸上。
